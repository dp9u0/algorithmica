来看下面这个小程序，我们计算一个整数数组的和：

```c++
const int n = 1e5;
int a[n], s = 0;

int main() {
    for (int t = 0; t < 100000; t++)
        for (int i = 0; i < n; i++)
            s += a[i];

    return 0;
}
```

用普通的 `g++ -O3` 编译并运行，它需要 2.43 秒完成。

现在，我们在文件最开头加上下面这条魔法指令：

```c++
#pragma GCC target("avx2")
// ...the rest is the same as before
```

在同一环境下编译运行，它只需 1.24 秒。这几乎快了一倍，而我们没有改动一行代码，也没有调整优化等级。

这里发生的事情是：我们提供了一点关于这段代码将要运行的计算机的信息。具体来说，我们告诉编译器，目标 CPU 支持 x86 指令集的一个扩展，名为"AVX2"。AVX2 是 x86 众多所谓"SIMD 扩展"之一。这些扩展所包含的指令运行在特殊的寄存器上，这些寄存器可以容纳 128、256 乃至 512 位的数据，采用的是"单指令多数据"（SIMD）方式。SIMD 指令不再只处理单个标量值，而是把寄存器中的数据切分成 8、16、32 或 64 位的块，对它们并行地执行同一个操作，从而带来成比例的性能提升[^power]。

[^power]: 在某些 CPU 上，尤其是重度使用的 SIMD 指令会消耗更多电能，因此需要[降频](https://blog.cloudflare.com/on-the-dangers-of-intels-frequency-scaling/)来平衡总功耗，所以实际提速并不总是成比例的。

![](/en/hpc/simd/img/simd.png)

这些扩展相对较新，它们在 CPU 中的支持是逐步实现的，同时保持着向后兼容[^avx512]。除了增加更多专用指令之外，它们之间最重要的区别是引入了越来越宽的寄存器。

具体来说，AVX2 提供操作 256 位寄存器的指令，而默认情况下 GCC 假定只启用了不超过 128 位的 SSE2。因此，在告诉优化器可以使用一次加 8 个（而不是 4 个）整数的指令之后，性能翻了一倍。

[^avx512]: 从 AVX512 开始，向后兼容不再保持：出现了许多针对特定需求（如数据压缩、加密或机器学习）定制的不同变体。

![](/en/hpc/simd/img/intel-extensions.webp)

编译器通常能很好地用 SIMD 指令改写简单的循环，就像上面的例子那样。这种优化叫做[自动向量化](auto-vectorization)，它也是使用 SIMD 最流行的方式。

问题在于它只对特定类型的循环有效，而且即便有效，结果也常常不是最优的。要理解它的局限，我们需要亲自动手，在更低的层面探索这项技术——这正是本章要做的。
