让编译器产出高性能的第一步是开口去要，具体是通过一百多种编译器选项、属性（attribute）和 pragma 完成。

### 优化级别

GCC 用于提速的主要优化级别有 4 个*半*：

- `-O0` 是默认级别，不做任何优化（不过从某种意义上说它也在优化：优化编译时间）。
- `-O1`（别名 `-O`）做少量"唾手可得"的优化，几乎不影响编译时间。
- `-O2` 启用所有已知几乎不产生负面副作用、耗时可接受的优化（大多数项目的生产构建用的就是它）。
- `-O3` 做非常激进的优化，启用 GCC 实现的几乎全部*正确*优化。
- `-Ofast` 包含 `-O3` 的全部，另加几个可能破坏严格标准合规性的优化标志，但破坏方式对多数应用都不致命（例如浮点运算可能被重排，导致结果的尾数差上几位）。

还有许多其他优化标志连 `-Ofast` 都不包含，因为它们高度依赖具体场景，默认启用更可能损害性能而非提升——[下一节](../situational)会讲其中一些。

### 指定目标平台

接下来你可能想做的是告诉编译器更多关于这段代码将在什么机器上运行的信息：目标平台集合越小越好。默认情况下，它会生成能在任何较新的（>2000 年）x86 CPU 上运行的二进制文件。缩小范围最简单的办法是传 `-march` 标志指定确切的微架构：`-march=haswell`。如果编译和运行二进制的是同一台机器，可以用 `-march=native` 自动检测。

指令集大体向后兼容，所以往往只用你所要支持的最老微架构的名字就足够了。更稳妥的做法是列出 CPU 保证具备的具体特性：`-mavx2`、`-mpopcnt`。当你只想针对某台机器*调优*（tune）程序、又不想使用任何在不兼容 CPU 上会让它崩溃的指令时，可以用 `-mtune` 标志（默认情况下 `-march=x` 也隐含 `-mtune=x`）。

这些选项也可以用 pragma 按编译单元指定，替代编译标志：

```c++
#pragma GCC optimize("O3")
#pragma GCC target("avx2")
```

当你只想优化单个高性能过程、又不想拖慢整个项目的构建时间时，这很有用。

### 多版本函数

有时你可能还想在同一个库里提供多个针对不同体系结构的实现。可以用基于属性的语法，让多版本函数在编译期自动选择：

```c++
__attribute__(( target("default") )) // fallback implementation
int popcnt(int x) {
    int s = 0;
    for (int i = 0; i < 32; i++)
        s += (x>>i&1);
    return s;
}

__attribute__(( target("popcnt") )) // used if popcnt flag is enabled
int popcnt(int x) {
    return __builtin_popcount(x);
}
```

在 Clang 里，不能用 pragma 从源代码设置 `target` 和优化标志，但属性可以像 GCC 一样使用。
